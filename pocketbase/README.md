# اتصال اپلیکیشن «مسیر کنکور» به PocketBase

اپلیکیشن به‌صورت **دستی** و **برای هر کاربر جداگانه** با ایمیل/رمز عبور به PocketBase وصل می‌شود.
این پوشه ابزار ساخت مجموعه‌ها (Collections) لازم روی سرور PocketBase را دارد.

---

## دو روش برای ساخت مجموعه‌ها

| روش | فایل | مناسب برای |
| --- | --- | --- |
| ایمپورت در پنل ۰.۴۰ | `pb_collections_panel.json` | سرور تازه؛ ساده‌ترین راه بدون نصب پایتون |
| اجرای اسکریپت | `setup_pocketbase.py` / `setup_pocketbase.bat` | سروری که از قبل داده دارد؛ بی‌خطرترین راه |

هر دو روش مجموعه‌های یکسانی می‌سازند. اگر سرورتان **تازه** است، روش ایمپورت در پنل کافی است.
اگر روی سرور از قبل مجموعه/داده دارید، روش اسکریپت را انتخاب کنید.

---

## روش ۱: ایمپورت در پنل PocketBase ۰.۴۰

1. وارد پنل ادمین شوید: `https://YOUR-SERVER/_/`
2. **Settings → Import collections**
3. فایل `pb_collections_panel.json` را انتخاب کنید.
4. در صفحهٔ مقایسه، تغییرات را ببینید و **Confirm and import** را بزنید.

این فایل شامل **۱۲ مجموعه** است: مجموعهٔ `users` (نسخهٔ پیش‌فرض ۰.۴۰.۶) به‌همراه ۱۱ مجموعهٔ اپلیکیشن.
حضور `users` در فایل ضروری است؛ در غیر این صورت ایمپورت پنل آن را حذف می‌کند و با خطا شکست می‌خورد.

### چرا فایل‌های قبلی ایمپورت نمی‌شدند؟

در PocketBase ۰.۴۰ صفحهٔ `Settings → Import collections` همیشه با حالت «حذف مجموعه‌های غایب»
(`deleteMissing = true`) اجرا می‌شود و کلید خاموش‌کردنش در پنل وجود ندارد. فایل‌های قبلی مجموعهٔ `users` را
نداشتند، پس اول `users` حذف می‌شد و یکی از این خطاها می‌آمد:

```
400 validation_collections_import_failure
The relation collection doesn't exist.   (collectionId)
```

```
400 validation_invalid_index_expression
SQL logic error: no such column: localId
```

### نکات ایمنی روش پنل

- حالت `deleteMissing` فقط مجموعه‌های **سیستمی** (`_superusers`, `_mfas`, `_otps`, `_externalAuths`,
  `_authOrigins`) را نگه می‌دارد؛ هر مجموعهٔ **غیرسیستمی** که در فایل نباشد حذف می‌شود.
  پس این فایل را فقط روی سرور **تازه** یا سروری که مجموعهٔ اضافی ندارد ایمپورت کنید.
- تعریف مجموعهٔ `users` (فیلدها، قواعد، تنظیمات ورود) با نسخهٔ پیش‌فرض ۰.۴۰.۶ جایگزین می‌شود.
  اگر روی `users` فیلد سفارشی ساخته‌اید، اول از آن خروجی بگیرید؛ فیلدهای حذف‌شده داده‌شان را هم از دست می‌دهند.
- ایمپورت مجدد همین فایل بی‌خطر است: شناسه‌ها یکی هستند، فیلدی حذف نمی‌شود و **رکوردها پاک نمی‌شوند**
  (تست‌شده: کاربران و داده‌ها بعد از ایمپورت دوباره سر جایشان ماندند).
- اگر مجموعه‌ها را با نسخهٔ قدیمی همین فایل ساخته‌اید، یک‌بار این فایل جدید را ایمپورت کنید. فیلدهای
  `created` و `updated` به ۱۱ مجموعهٔ اپلیکیشن اضافه شده‌اند و همان پایهٔ «سینک تدریجی» هستند.
  ایمپورت فقط ستون‌های زمانی را اضافه می‌کند؛ رکوردهای موجود حفظ می‌شوند و زمان‌شان با اولین ویرایش پر می‌شود.
- بعد از ایمپورت، حتماً یک‌بار **Refresh** پنل را بزنید تا مجموعه‌ها به‌روز شوند.

## روش ۲ (بی‌خطرترین): اجرای اسکریپت `setup_pocketbase.py`

این اسکریپت فقط از کتابخانهٔ استاندارد پایتون استفاده می‌کند (پایتون ۳.۸+ کافی است) و:

- مجموعه‌های لازم را **می‌سازد** یا اگر از قبل هستند **به‌روزرسانی** می‌کند،
- **هیچ چیزی را حذف نمی‌کند** (نه مجموعه، نه رکورد)،
- فیلدهای جامانده (`order`, `examId`, `created`, `updated`, …) را اضافه می‌کند،
- فیلد `owner` را به مجموعهٔ کاربران وصل می‌کند،
- قواعد دسترسی هر کاربر و ایندکس یکتای (`localId`, `owner`) را می‌سازد،
- به مجموعهٔ `users` و حساب‌های موجود **دست نمی‌زند**،
- اجرای مکرر آن بی‌خطر است (idempotent).

### اجرا

```bash
python setup_pocketbase.py --url https://masir-69623a.dockhold.app --email ADMIN_EMAIL
# رمز سوپرکاربر پرسیده می‌شود
```

نمونه‌های دیگر:

```bash
# فقط نمایش تغییرات، بدون اعمال
python setup_pocketbase.py --url https://... --email admin@example.com --dry-run

# بدون پرسش تعاملی (مثلاً برای اسکریپت خودکار)
python setup_pocketbase.py --url https://... --email admin@example.com --password '...'
```

خروجی موفق چنین است:

```
created  settings
...
Done: created=11 updated=0 unchanged=0
```

`--email` و `--password` مربوط به **سوپرکاربر PocketBase** است (حساب پنل ادمین)، نه حساب کاربران اپ.

> اگر مجموعه‌ای با همان نام ولی فیلد هم‌نامِ نوع‌متفاوت روی سرور داشته باشید، اسکریپت متوقف می‌شود و
> نام همان مجموعه/فیلد را می‌گوید تا در پنل اصلاح کنید؛ هیچ تغییری به‌زور اعمال نمی‌شود.

### ویندوز بدون پایتون

فایل `setup_pocketbase.bat` را دوبار کلیک کنید؛ نسخهٔ PowerShell (`setup_pocketbase.ps1`) اجرا می‌شود و
آدرس سرور، ایمیل و رمز را می‌پرسد. برای فقط دیدن تغییرات:

```powershell
powershell -ExecutionPolicy Bypass -File setup_pocketbase.ps1 -DryRun
```

## راه پیشرفته: ایمپورت JSON از طریق API

فایل `pb_collections.json` همان ۱۱ مجموعهٔ اپلیکیشن است **بدون** `users` و برای ایمپورت از طریق API.
باید `deleteMissing = false` بفرستید؛ در غیر این صورت همان خطای حذف `users` رخ می‌دهد.

```bash
# 1) توکن سوپرکاربر
TOKEN=$(curl -s -X POST "$URL/api/collections/_superusers/auth-with-password" \
  -H 'Content-Type: application/json' \
  -d '{"identity":"ADMIN_EMAIL","password":"ADMIN_PASSWORD"}' | jq -r .token)

# 2) ایمپورت بدون حذف چیز دیگر — متد PUT است، نه POST
jq -n --slurpfile c pb_collections.json '{collections:$c[0], deleteMissing:false}' \
| curl -s -X PUT "$URL/api/collections/import" \
  -H "Authorization: $TOKEN" -H 'Content-Type: application/json' -d @-
```

پاسخ موفق: `204 No Content`. سپس همین اسکریپت `setup_pocketbase.py` را هم یک بار اجرا کنید تا مطمئن شوید
همه‌چیز کامل است.

> فایل `pb_collections_panel.json` مخصوص پنل است (چون `users` را هم دارد). آن را با این روش API ایمپورت نکنید.

## مراحل اتصال اپلیکیشن

1. مجموعه‌ها را با یکی از روش‌های بالا بسازید.
2. در پنل PocketBase → مجموعهٔ **users** → **New record**: برای هر کاربر اپ یک حساب با ایمیل و رمز بسازید
   (اپ ثبت‌نام نمی‌کند و فقط با حساب موجود وارد می‌شود).
3. در اپ: **تنظیمات → همگام‌سازی ابری** → ایمیل/رمز خودِ کاربر را بزنید و **ورود** را بزنید.
   آدرس سرور داخل اپ ثابت است و کاربر آن را نمی‌بیند.
4. پس از ورود، همگام‌سازی خودکار شروع می‌شود: تغییرات این دستگاه با تأخیر کوتاه ارسال و تغییرات حساب
   با فاصلهٔ زمانی کم‌حجم دریافت می‌شوند. دکمهٔ **همگام‌سازی اکنون** برای اجرای فوری و دستی است.

> اگر هنگام ورود/ارسال خطای ۴۰۴ دیدید، یعنی مجموعه‌ها روی سرور ساخته نشده‌اند؛
> `pb_collections_panel.json` را در پنل ایمپورت کنید یا `setup_pocketbase.py` را اجرا کنید.

### خطای «Too Many Requests» (۴۲۹)

PocketBase روی هر IP محدودیت تعداد درخواست دارد. مقدارهای پیش‌فرض:

| قاعده | سقف | بازه |
| --- | --- | --- |
| `*:auth` (ورود) | ۲ درخواست | ۳ ثانیه |
| `*:create` (ساخت رکورد) | ۲۰ درخواست | ۵ ثانیه |
| `/api/batch` | ۳ درخواست | ۱ ثانیه |
| `/api/` (کل API) | ۳۰۰ درخواست | ۱۰ ثانیه |

در ارسال اول (وقتی همهٔ رکوردها تازه ساخته می‌شوند) سقف `*:create` می‌تواند پر شود. اپ خودش این حالت را
مدیریت می‌کند: پیام «سرور محدودیت درخواست گذاشته؛ تلاش دوباره…» را نشان می‌دهد و با تأخیر فزاینده
دوباره تلاش می‌کند. همگام‌سازی خودکار در صورت خطا عقب می‌کشد و بعداً دوباره امتحان می‌کند؛ لازم نیست
کاری انجام دهید. ارسال دوباره هم بی‌خطر است: رکوردهای موجود به‌روزرسانی می‌شوند و رکورد تکراری ساخته نمی‌شود.

اگر می‌خواهید ارسال اول سریع‌تر شود، در پنل → **Settings → Rate limits** محدودیت را موقتاً خاموش کنید،
ارسال را انجام دهید و بعد دوباره روشن کنید. (روشن‌بودن آن برای امنیت سرور بهتر است.)

## مجموعه‌ها و فیلدها

| مجموعه | کاربرد | فیلدها |
| --- | --- | --- |
| `settings` | پروفایل، تنظیمات، شمارنده‌های تراز | `owner`, `localId`, `value` |
| `subjects` | درس‌ها | `owner`, `localId`, `value`, `order` |
| `activities` | فعالیت‌های روزانه | `owner`, `localId`, `value`, `order` |
| `classes` | کلاس‌ها | `owner`, `localId`, `value`, `order` |
| `sessions` | جلسات برنامه | `owner`, `localId`, `value`, `order` |
| `sleeps` | خواب | `owner`, `localId`, `value`, `order` |
| `phones` | استفاده از گوشی | `owner`, `localId`, `value`, `order` |
| `exams` | آزمون‌ها | `owner`, `localId`, `value`, `order` |
| `questions` | سؤالات آزمون | `owner`, `localId`, `value`, `order`, `examId` |
| `plan` | دادهٔ قدیمی برنامه (مهاجرت) | `owner`, `localId`, `value`, `order` |
| `reserved` | دادهٔ قدیمی رزرو (مهاجرت) | `owner`, `localId`, `value`, `order` |

- `value` از نوع **JSON** است و ساختار داخلی رکورد را نگه می‌دارد.
- `owner` از نوع **Relation** به مجموعهٔ `users` است (شناسهٔ پیش‌فرض `_pb_users_auth_`؛ اگر شناسهٔ مجموعهٔ
  کاربران شما متفاوت باشد، اسکریپت خودش آن را پیدا و وصل می‌کند).
- هر مجموعه ایندکس **یکتا** روی (`localId`, `owner`) دارد.
- قواعد دسترسی فقط به رکوردهای خود کاربر اجازه می‌دهند:

```
list/view : owner = @request.auth.id
create    : @request.auth.id != "" && owner = @request.auth.id
update    : owner = @request.auth.id
delete    : owner = @request.auth.id
```

## نکات مهم

- `pb_collections.json` مجموعهٔ `users` را ندارد و اسکریپت هم به آن دست نمی‌زند؛ حساب‌های موجود سرور دست‌نخورده می‌مانند.
  فقط `pb_collections_panel.json` (مخصوص ایمپورت پنل) شامل `users` است.
- **همگام‌سازی خودکار است:** هر تغییر محلی پس از حدود ۷ ثانیه بی‌کاری ارسال می‌شود، بین دوره‌ها حداقل ۳۰
  ثانیه فاصله است و دریافت زودتر از هر ۶۰ ثانیه تکرار نمی‌شود. یک بررسی دوره‌ای هر ۱۰ دقیقه (فقط وقتی
  تب مرورگر فعال است) تغییرات سایر دستگاه‌ها را می‌گیرد. با این فاصله‌ها سرور تحت فشار نیست.
- **بدون تغییر، بدون درخواست:** اگر هیچ تغییر ارسال‌نشده‌ای نباشد، ارسال خودکار هیچ درخواستی به سرور نمی‌فرستد.
- **سینک تدریجی است:** هر بار اول یک فهرست سبک از سرور خوانده می‌شود (شناسهٔ رکورد و زمان آخرین تغییر،
  بدون مقدارها) و فقط رکوردهای تغییرکرده ارسال یا دریافت می‌شوند. اولین سینک هر حساب/سرور کامل است تا
  پایهٔ مقایسه ساخته شود؛ از سینک دوم به بعد فقط تغییرات جابه‌جا می‌شوند.
- **پیش‌نیاز سینک تدریجی:** مجموعه‌ها باید فیلدهای `created` و `updated` را داشته باشند (در فایل‌های JSON
  همین پوشه هستند). اگر سرور با فایل قدیمی ساخته شده باشد، سینک باز هم امن است: زمان تغییر «نامعلوم»
  در نظر گرفته می‌شود و رکوردها دوباره خوانده می‌شوند تا تغییری از دست نرود. بعد از یک‌بار ایمپورت فایل
  جدید و ویرایش رکوردها، سینک سبک و واقعاً تدریجی می‌شود.
- **ترتیب چرخه:** اول تغییرات این دستگاه ارسال می‌شود، بعد تغییرات سرور دریافت می‌شود. اگر ارسال ناموفق
  باشد، دریافت انجام نمی‌شود تا ویرایش‌های ارسال‌نشده از بین نروند.
- **اولین سینک:** اگر این دستگاه دادهٔ مطالعه دارد (فعالیت، آزمون، جلسه، خواب، گوشی یا شمارندهٔ تست)، اول
  ارسال می‌شود؛ اگر دستگاه تازه باشد، اول داده‌های حساب دریافت می‌شود تا چیزی بازنویسی نشود.
- اگر این دستگاه تغییر محلیِ هنوز ارسال‌نشده داشته باشد و همان رکورد روی سرور هم عوض شده باشد، چون اول
  ارسال انجام می‌شود نسخهٔ این دستگاه روی سرور می‌نشیند و بعد دریافت، نسخهٔ سرور را روی دستگاه می‌آورد.
- دریافت بدون بارگذاری مجدد صفحه انجام می‌شود و نمای فعلی تازه می‌شود. اگر همان لحظه مشغول تایپ در یک
  فیلد یا باز بودن پنجرهٔ گفتگو باشی، دریافت به چند ثانیهٔ بعد موکول می‌شود.
- **آفلاین:** وقتی اینترنت قطع است هیچ درخواستی فرستاده نمی‌شود؛ پس از وصل‌شدن، همگام‌سازی خودکار ادامه می‌یابد.
- پیش از اولین همگام‌سازی، از داده‌های محلی خروجی پشتیبان بگیرید (تنظیمات → پشتیبان‌گیری).
